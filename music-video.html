Getting Past the 25 MB / 100 MB File Limit on GitHub Pages

1. Slice Video Into 4-Second HLS Chunks (Pages-Native)

GitHub blocks files ≥ 100 MB in Git (and 25 MB on web upload). Slice any large .mp4/.mov into ~2–4 MB .ts segments with scripts/slice_hls_video.sh, commit the folder, and open it with ?hls=:

./scripts/slice_hls_video.sh ~/Movies/donkey-water.mp4 video/cut
# Then test:
music-video.html?hls=./video/cut/playlist.m3u8

2. GitHub Releases (Single MP4 up to 2 GB)

Keep the repo slim by attaching the full .mp4 to a GitHub Release on hartswf0/make-photo, or using YouTube embed, and load via URL query:

gh release create v1.0-video ~/Movies/cut.mp4 --title "Cut"
# Then pass: ?mp4=<release-asset-url>

3. Large Single-File HTML (External Assets + Split Data)

Why night-post/ and zones/ stay under 1 MB of HTML: load shared textures, Three.js, and MONOLITH-3.html assets relatively instead of base64-inlining everything into one monolith file. Chat attachments also don't need re-uploading when files already live in ~/Downloads or this repo — just cite the path with @[...].
